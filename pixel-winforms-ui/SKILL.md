# Windows 白底重像素 UI

## 目标

在不牺牲可读性、键盘操作和状态准确性的前提下，建立可复用的白底重像素 WinForms 界面。先统一设计语言，再实现控件，最后验证视觉与运行稳定性。

## 必读资源

- 设计或改造页面前，读取 `references/design-system.md`，确定颜色、字号、边框、间距和窗口尺寸。
- 实现自绘控件、列表刷新、弹窗或滚动区域前，读取 `references/component-patterns.md`。
- 新项目可复制 `assets/PixelTheme.cs` 与 `assets/DpiSupport.cs`，修改命名空间后使用；已有主题系统则只移植需要的部分，避免平行维护两套主题。

## 工作流程

### 1. 盘点现有界面

- 列出所有窗口、弹窗、托盘菜单、进度窗口、列表、滚动区域和图标入口。
- 记录每个页面的尺寸、背景、字体、边框、对齐、可否拖动及刷新方式。
- 标出原生 `MessageBox`、系统滚动条、圆角、渐变、抗锯齿图形和不一致图标。
- 保留用户已有布局意图；只在占地、层级或一致性确有问题时调整结构。

### 2. 确定统一规格

- 使用纯白主背景、近黑粗边框、直角矩形和整数像素坐标。
- 优先采用 `760×438` 以内的固定窗口；内容较少时继续缩小，不为留白扩大窗口。
- 标题栏、内容边框、分栏线和底栏使用同一粗细体系。
- 能居中的标题、按钮和短提示居中；长说明、列表字段和日志保持左对齐。
- 中文正文使用清晰的系统中文字体；像素感主要由几何、边框、阴影和控件结构承担，不强迫正文使用难读的像素字体。

### 3. 建立主题基础

- 先集中定义颜色、字体、标签工厂、窗口绘制和菜单渲染，再修改业务页面。
- 所有窗口使用同一应用图标；任务栏、标题栏、托盘和安装程序不得混用旧图标。
- 无边框窗口必须支持标题区拖动、Esc 关闭或取消、Enter 确认，并在显示后校正到可见屏幕区域。
- 为自绘按钮、开关和进度条保留键盘焦点、Tab 顺序和可访问名称。

### 4. 统一控件

- 使用自绘按钮表现普通、悬停、按下、选中、危险和焦点状态。
- 使用像素菜单渲染器统一菜单宽度、行高、选中底色和外框。
- 对视觉关键区域使用自绘滚动条；只读日志可把原生文本区包在像素外框和像素滚动条内。
- 更新进度使用分段像素进度条，并同时显示文字状态和百分比。
- 禁止直接使用系统 `MessageBox`；确认、错误、更新和完成提示都使用统一像素弹窗。

### 5. 分离状态更新与界面重绘

- 后台状态采集、计时和业务处理持续运行，不因弹窗或页面打开而暂停。
- 只有内容签名变化时才更新页面；不要在定时器每次触发时清空并重建全部控件。
- 必须重建复杂页面时，关闭中间重绘，完成后一次性恢复并刷新。
- 列表绘制上限必须同时受“布局容量”和“实际集合数量”约束，禁止只按剩余空间计算索引。
- 使用防重入标志包围刷新逻辑；弹窗嵌套消息循环期间也不得进入第二次重绘。

### 6. 验证

- 编译并运行应用，逐页检查背景、边框、字体、图标、菜单、滚动条和弹窗。
- 在 100%、150%、200% 缩放下检查裁切、错位和不可点击区域。
- 覆盖空列表、单条、刚好满页、超过容量和多种状态混合的列表场景。
- 连续打开窗口并观察至少三个刷新周期，确认没有闪烁、越界或控件跳动。
- 用键盘完成 Tab 导航、Enter 确认、Esc 取消，并检查焦点框可见。
- 截图对比所有页面；发现一个非像素控件时，继续追查同类控件而不是只修单页。

## 强制规则

- 不使用圆角、渐变、半透明玻璃和柔化阴影。
- 不在整数像素边框上启用抗锯齿。
- 不用大面积黑底制造像素感；主体保持白底，只用黑线建立层级。
- 不让页面尺寸随列表条数无限增长；使用固定内容区、分页、更多页或滚动区域。
- 不以暂停状态采集来解决界面闪烁。
- 不在刷新过程中访问超过集合实际数量的行。
- 不复制业务名称、版本号或品牌图标到通用模板。

## 交付自检

- [ ] 所有窗口使用统一白底、粗边框和直角控件。
- [ ] 窗口大小与内容匹配，空白不过量，最大尺寸符合约束。
- [ ] 标题、按钮和短提示在适合时居中。
- [ ] 所有窗口可拖动且不会移出可见屏幕。
- [ ] 菜单、滚动条、弹窗、进度条和图标已统一。
- [ ] 状态采集未暂停，界面刷新无闪烁、无重入、无越界。
- [ ] DPI、键盘和可访问性检查通过。
- [ ] 模板中不存在业务专用名称、路径、版本和资源。
